Why orchestration

Business logic, scattered.

  • todayProcess steps live inside cron jobs, message handlers, and tribal knowledge — no single place shows what a process actually does.
  • todayWhen something is stuck, you grep logs across five services to find out why.
  • todayChanging the order of steps means a code change, a review, and a deploy.

The platform

One diagram, executed.

BPMN isn't documentation of the process — it is the process.

BPMNThe diagram. Defines steps, order, and decisions.
ZeebeThe engine. Runs instances, scales horizontally.
DMNDecision tables, modeled separately. A business rule task calls one.
ConnectorsPrebuilt steps, configured not coded — both outbound (Charge Payment) and inbound (webhook).
FormsA JSON schema on a user task — Tasklist renders it, no frontend code.
Boundary eventsTimer, error, and message — three ways to interrupt a task.
Multi-instanceRun one activity per element of a collection, not once per instance.
OperateWatch every instance live. See exactly where it's stuck.
TasklistWhere humans complete the manual steps.

When it breaks

No crash. No redeploy.

Bad input reaches the worker — instead of losing the instance, Zeebe holds it exactly where it failed.

POST /orders {"order_id":"ORD-1003","quantity":0}

Incident · Task_ValidateOrder

Failed job. Error: Invalid quantity 0 for order ORD-1003

Without orchestration

A failed script exits. Someone notices a missing order, hours later, from a support ticket.

With Zeebe

Operate shows the exact instance and error. Fix the variable, click retry, the instance continues — mid-flow.

Not every incident is a bug

Three more endings.

Boundary events race the task they're attached to — first one to happen wins, and each ends the instance differently.

  1. Payment declined — error boundary event

    The connector's errorExpression turns an HTTP 402 into a BPMN error. Caught, not crashed — no incident, just a different ending.

    POST /orders {"order_id":"ORD-2001","quantity":10}

  2. Canceled — message boundary event + inbound connector

    A real external call interrupts a running instance from outside — the same pattern a customer portal or support tool would use.

    POST /orders/ORD-2002/cancel

  3. Escalated — timer boundary event

    Leave "Confirm Delivery" untouched for a minute and it fires on its own — no API call, just the passage of time.

Why it matters

What you actually get.

  • seeEvery instance, live. Not logs to reconstruct — an actual, current picture of what's running and where it's stuck.
  • changeReroute without a deploy. The gateway condition reads a DMN decision, not a code branch.
  • mixAny language, per step. The order-triggering service is Python; the payment service the connector calls is Node — proven, not hypothetical.
  • trustNothing silently drops. A failed job becomes a visible, fixable incident; a business failure becomes a modeled boundary event — never a swallowed exception.
